## Auth, errors, version gate
Bearer JWT (HS256, 30 days, payload {id, sv}). **One login per user**: login/activate rotate users.session_id; a token whose sv differs -> 401 `SESSION_REPLACED` (ws close 4409); session_id NULL accepts only tokens without sv (smooth rollout). Errors `{error, code?}`: 401, 403 `Not allowed` (NOT_ALLOWED), 404 (NOT_FOUND), 500. Header `X-App-Version` below `minVersionCode` -> 426 `UPDATE_REQUIRED` (ws: close 4426). GET /app/version, GET /health, `/download/*` are public.

## /chats (member of the chat)
- GET /chats, POST /chats `{name, memberIds}`, POST /chats/dm `{userId}`, GET /chats/:id (any chat type incl. dm) -> `{chat, members:[{id,name,role,phone,avatarEmoji,isCreator}], tasks}` (open tasks made in the chat + for DMs tasks shared by the two; brief shape for tasks the viewer cannot open), POST/DELETE members, PATCH /chats/:id `{name}`, PATCH /chats/:id/me `{muted?, pinned?}`, POST /chats/:id/pin `{messageId|null}` (any member, any non-ephemeral message incl. bot cards; ws `pin`), GET /chats/:id/messages?limit&before|after&**kind=all|ai|chat** (ai = bot cards, chat = human text), POST /chats/:id/read (unchanged from round 1).
- POST /chats/:id/messages `{text (max 4000), clientId, replyToId?, mentionIds?: number[]}` -> 201 `{message}` (dup clientId -> 200 `duplicate:true`).
  - **mentionIds** (structured mentions from app pickers, in text order): each `@token` in the text takes the first unused id whose name matches it (`names.tagMentions`); those ids are trusted as-is (same-name people). Other `@tokens`: chat members by first name (one hit), else fuzzy; only a SINGLE hit counts (ambiguous = no mention). `message.mentions` = all ids.
  - **Task link at send time** (messages.task_id): a reply inherits the parent's task_id (reply chains, any depth); else a plain text with exactly one `#N` the sender can view. Commands set it after resolving their task.
  - After the reply: slash command (with the tagged mentions) -> else `handleLinked` (task-linked message, see Slash commands) -> else AI engine. Check-in chat text (not a command) is also stored as today's check-in text.
- Message object: `{id, chatId, senderId, senderName, senderEmoji, text, deleted, clientId, createdAt, editedAt, type, payload, replyTo, visibleTo, mentions, reactions, sourceMessageId, taskId}`.

## Messages / users (routes/misc.js)
- **PATCH /messages/:id** `{text, mentionIds?}` -> `{message}`: own `text` message only, not ephemeral/deleted, within 10 min of sending (everyone, boss too). Old body -> message_revisions, `edited_at` set, mentions re-read; ws `{type:'edited', chatId, message}`. Commands are not re-run. **Edit propagation**: a task this message created (< 10 min, open, by the author) gets the re-parsed title / description / due (never assignees or status; source `edit`); notes made from it are updated (+ event `note_edited`); a description it set is re-applied; attached cards rewritten (ws `edited`). 403 `{code:'EDIT_WINDOW'}` after 10 min, 403 NOT_ALLOWED for others' / bot / system messages.
- **DELETE /messages/:id** (soft): own text message within 10 min (boss too), or your own ephemeral bot card any time. Same 403 codes. ws `deleted`. A note made from the message becomes event `note_deleted`; a task it created stays open.
- POST/DELETE /messages/:id/reactions (toggle mine; ws `reaction`). GET /users -> `{users:[{id,name,phone,role,avatarEmoji}]}` (active, not bot, not self; `?includeSelf=1` adds me).

## /tasks
Task: `{id,title,description,project,assigneeId,assigneeName (primary),assignees:[{id,name,avatarEmoji,status,completedAt,updatedAt}],createdBy,createdByName,status (aggregate),dueDate,chatId,sourceMessageId,createdAt,updatedAt,completedAt,closedAt,closedBy,overdue,ageDays,stale,remindedAt}`. Brief: `{id,title,status,assigneeNames,assigneeIds,brief:true}`.
Permissions: view = boss, active assignee or creator (else 403 / brief). Own status = that assignee; anyone's = boss or creator (+membersCanAssign). Note/description = boss, assignee, creator. Title/project/due/people = boss, or (membersCanAssign) creator/assignee. Create = boss / membersCanAssign / a self-task. Close/reopen = boss or creator.
- GET /tasks `?scope=mine|everyone|all&status=<key>|open|closed&q (text or #12)&project&assignee=<id>&with=<userId>&limit<=200&before=<id>&ids=1,2,3`. `ids` (<=100): exactly those tasks, no scope / status / 14-day filter (chat cards read current state); private tasks of others hidden; member gets brief for tasks not viewable. Boss default all; member default mine (assigned OR created). Member `everyone` = non-closed tasks, brief unless viewable. `with` = tasks shared by me and that user (boss: all of theirs). No status = open + done/closed of the last 14 days.
- GET /tasks/:id -> `{task, events}`; events have `subjectId/subjectName` and `source {messageId, chatId, chatName, chatType, senderName, text, replyTo, createdAt, available, deleted}` (text only for current members of that chat; purged -> snapshot, available false).
- GET /tasks/summary -> per person by own status (`todo..done, overdue, doneToday`, closed excluded) + team `totals` (open, each step, closed, doneToday, overdue); members get only their row. GET /tasks/activity (members: viewable tasks only). GET /tasks/mine/summary.
- POST /tasks `{title, description? (<=4000), assigneeIds:[1..10] | assigneeId, dueDate?, project?, chatId?}`. PATCH /tasks/:id `{status?, userId?|userIds?, title?, description?, project?, dueDate?, note?, assigneeIds? (replace), addAssigneeIds?, removeAssigneeIds?}` (400 TASK_CLOSED, LAST_ASSIGNEE). Status without userId = me if assignee, else all (boss/creator).
- POST /tasks/:id/close `{reason?<=300}` | /reopen (back to the aggregate) | /undo (last status change of that person) | /praise. DELETE /tasks/:id = close (old apps).
- ws `{type:'task', task, event, actorId, actorName, notifyAdmin}` to bosses, assignees, creator, actor (+ removed people, + the asker for `answered`). Events: created, completed (task done), planning/coding/testing/change_merged/done (one person), updated, reassigned, due, note, closed, reopened, answered, praise. Writes run in a transaction; events batch-inserted; users cached in memory (src/users.js).

## /updates (OTA, expo-updates protocol v1, no auth, before the 426 gate)
- `GET /updates/manifest` headers `expo-platform: android`, `expo-runtime-version: <rv>`: serves newest folder of `server/updates/<rv>/<timestamp>/` (`expo export` output + `expoConfig.json`) as multipart/mixed (`manifest` + `extensions`); same `expo-current-update-id` + protocol 1 -> `noUpdateAvailable` directive. 400 bad platform/runtime, 404 no folder.
- `GET /updates/assets?asset=<rv>/<ts>/<path>&runtimeVersion=<rv>&platform=android`: file inside `server/updates/<rv>/` only (traversal -> 400), immutable cache.
- Optional env `PUBLIC_BASE_URL` (e.g. `https://apps.landauditors.com/team_chat`) = base for asset URLs; default request protocol+host.

## Slash commands (ai/commands.js)
`/task @A [@B] <text> [due X]` (also `khud`/`me`/`mujhe`/`mere liye` = self; "A aur B", "A, B"), `/update [#id] <note>`, `/planning` `/coding` (`/start`) `/testing` (`/review`) `/merged` `/done` `[#id] [@name] [note]`, `/status #id <step>` (no step = /ask), `/assign #id @A` (add), `/unassign #id @A`, `/reassign #id @A [@B]` (replace), `/due #id <date|none>`, `/close #id [reason]` (`/delete`), `/reopen #id`, `/ask #id`, `/desc #id <text>`, `/tasks [name]` (members: brief), `/mytasks`, `/help`. Disabled -> COMMANDS_DISABLED; unknown -> BAD_COMMAND. Status commands: assignee = own status; boss/creator = everyone or only the `@name`s.
- **Person resolution**: tagged `@word` (mentionId) wins; else `names.bestMatches` on the first 1-2 words (exact > prefix > skeleton > edit distance; chat members first); `/task` may name people later ("... anubhav ko", `@word` anywhere). Several equal matches -> AI `pickPerson` (>= 0.8) -> else **userpicker** `{kind:'userpicker', command, text, users, arg, pre, keep:[{label,id}]}`: app re-sends `'/' + command + (pre?' '+pre:'') + ' @' + firstName + (arg?' '+arg:'')` with `mentionIds:[...keep ids, id]`. Unknown name -> picker of me (first, "(Me)") + chat members / everyone.
- `/ask #id`: card `{kind:'ask', task, actorId, actorName, askId, askerId, assigneeId, assigneeIds}` mentioning every not-done assignee in this chat (others get it in a DM with the asker); task event `ask`.
- **handleLinked** (message with task_id, not a command, sender boss/assignee/creator; others: linked but nothing): direct reply to a task/ask/reminder card -> note + status words (card follows); `desc: ...` -> description; assignee replying to an ask card, or to a boss/creator message of the task ending with `?` -> answer (description if empty and asker boss/creator, else note; own status words) + asker notified (`answered`); deeper chain replies and plain `#N` messages -> note only (source `chain`, no card, no status).
- Cards carry `replyTo` (= messages.source_message_id); other payloads: picker, list (slim), help, error, info, reminder `{task, days, assigneeId}`.

## AI (ai/provider.js, ai/engine.js)
Provider used only with known name + key + `aiEnabled`; errors typed (AI_KEY_INVALID, AI_QUOTA, AI_TIMEOUT, AI_ERROR), logged as code only, mock answers instead, `lastError` in Admin Settings. ## Daily check-ins (checkins.js, round 2)
Card task rows carry the member's OWN status (`status`) + `taskStatus` (aggregate). Private `checkin` chat per member (member + bot; privacy guard `realtime.MEMBER_OK`). Bosses get none. Scheduler (1-min tick, TZ) on check-in days:
- From `morningTime` (10:00): `checkin_prompt` card `{kind:'day', date, tasks:[{id,title,status,dueDate,project,overdue,stale,ageDays}], counts}` = all open tasks; **pinned** in that chat. Every task change of the member rewrites the card (and today's sign-off card) payload: ws `{type:'edited', chatId, message}` (no `editedAt`).
- From `eveningTime` (18:00): `{kind:'signoff', date, tasks (open + done today), counts:{given,done,left}}`; one nudge card (`nudge:true`) after `nudgeMinutes` if not signed off.
- GET /checkins/today -> `{date, chatId, settings, workday, eveningOpen, day:{prompted, messageId}, signoff:{prompted, submitted, signoff}, tasks, doneToday, counts}`.
- **POST /checkins/signoff** `{taskStatuses?: {"<id>": <step>}, note?}` (members, own assigned tasks; old keys aliased; sets the member's own status; 400 `Invalid taskStatuses` / `Invalid task (use your own tasks only)`) -> 201 new / 200 update `{signoff:{id,userId,date,note,counts,tasks,messageId,...}, created, tasks (changed)}`. Applies statuses (source checkin), posts a member message summary, refreshes the cards, ws `{type:'signoff', userId, userName, date, counts, updated}` to bosses (quiet notification). The old POST /checkins (morning/evening forms) is removed.
- GET /checkins/mine?from&to -> `{from, to, checkins, signoffs}`. Boss: GET /admin/checkins?date -> `{date, workday, members:[{id,name,active, signoff:{status submitted|missing, prompted, signoff}, morning, evening}]}`; /admin/checkins/user/:id (same + signoffs); GET/PUT /admin/checkins/settings `{enabled, morningTime, eveningTime, days, nudgeMinutes}` (migrate_008 sets 10:00 / 18:00).

## Jobs (jobs.js, 1-min tick, once per local day via `job.<name>.lastRun`)
- `purge` Sunday >= 23:00, needs retentionEnabled: **hard-deletes** messages older than messageRetentionDays in every chat except each chat's pinned message and today's check-in cards; reactions + revisions deleted, replies / task source / prompt links set NULL; dump `server/backup/purge-YYYY-MM-DD.json` first; media files of purged messages deleted unless another message (forward) or a profile photo still uses them; ws `purged`. (Owner asked for real deletion here: overrides the soft-delete rule for retention only.)
- `reminders` daily >= morningTime, taskReminderDays > 0: open tasks created >= N days ago, once (`reminded_at`): bot card `{kind:'reminder', task, days, assigneeId}` in the check-in chat of every not-done active assignee + ws `task_stale` to bosses and them.
- `taskcleanup` daily >= 01:00, needs retentionEnabled: hard-deletes ONLY done / closed tasks (+assignees, events; messages.task_id nulled) whose completed_at / closed_at is >= taskDeleteDays ago (open tasks never); dump `server/backup/tasks-YYYY-MM-DD.json`; ws `{type:'tasks_purged', taskIds}`.
- `morning` / `evening`: post (or refresh) the check-in cards now (debug route only; normally checkins.js).

## WebSocket
`ws://host:port/?v=<versionCode>` with header `Authorization: Bearer <JWT>` (`?token=` still accepted for old apps; drop once min >= 4); 4401 bad token / logged out, 4409 SESSION_REPLACED, 4426 old version. Server -> client: `hello`, `message`, `edited`, `deleted`, `read`, `typing`, `chat`, `task`, `user`, `task_stale`, `tasks_purged`, `signoff` (bosses), `users`, `reaction`, `pin`, `settings`, `purged`, `reset`. Client -> server: `typing`.

## Backup / security
Nightly `server/backup/YYYY-MM-DD.json` after BACKUP_HOUR (all tables incl. signoffs, task_assignees; no pin_hash/session_id/invites; last 30 kept; `npm run backup`). Purge / cleanup / reset dumps are extra files (not rotated). PIN bcrypt, invite SHA-256, lockout (login + activate), auth rate limit, single session, headers nosniff / DENY / no-referrer, no x-powered-by, JSON body max 64 KB (413), trust proxy loopback, secrets only in `.env`, soft delete everywhere except the retention jobs and admin reset, SQL parameterized, AI output strictly parsed + permission-checked.
